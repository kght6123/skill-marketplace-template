# 段階的な導入

**最初から全部自動化しない。** 長いメモが大量に生成されて読む量が増えると、
「AIより人間の理解や指示が遅い」という元の問題に戻る。テンプレートが固まってから自動化する。

段は `orch.config.json` の `phase` で決める。AIはこの値に従うだけで、人に確認しない。

| phase | 入れるもの | スクリプトの強制 |
|---|---|---|
| 1 | `orch-issue-memo` を手で呼ぶ。理解メモの長さと粒度が安定するまでここで止める | なし（運用の目安） |
| 2 | `orch init` → `orch sync`。スタンプの読み取りと状態遷移を自動化 | なし（運用の目安） |
| 3 | `orch next` の1画面（今やること＋行列の件数） | なし（運用の目安） |
| 4 | `orch-implement` とPRテンプレート | **あり** |
| 5 | `orch merge-train` | **あり** |

4 と 5 だけはスクリプトが実際に止める。

| phase | 止まるもの |
|---|---|
| < 4 | `orch next --mode build` が空を返す。`orch worker` はエラーで止まる |
| < 5 | `orch merge-train` が何もせず返す |

既定は 5（全部有効）。段階的に入れたいときは 1 から始めて、手応えが出たら上げる。

```bash
node "$ORCH" phase --human      # 今の段と、何が止まっているか
```

## 各段で見るもの

**1 → 2 に上げる目安**: 理解メモに🚀がそのまま付くようになったとき。
毎回どこかを直しているうちは、テンプレートか生成ルールがまだ合っていない。
`orch lint memo` が通っても人が直すなら、それは lint の項目ではなく中身の問題。

**2 → 3**: 状態遷移が期待どおりか。`orch state list` で status が滞留していないか見る。

**3 → 4**: `orch next` が出す1件が、実際に「次にやるべきこと」になっているか。
順番に納得できないうちは実装を足さない。行列が伸びるだけになる。

**4 → 5**: PRのセルフレビューと指摘対応が回っているか。
マージを自動化するのは、その前段が安定してから。
