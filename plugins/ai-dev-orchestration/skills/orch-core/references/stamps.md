# スタンプ運用

AIはスタンプを押さない。読むだけ。判定は `orch sync` が行う。

## 割り当て

| 意味 | 既定 | リアクション名 |
|---|---|---|
| 承認・着手OK | 🚀 | `rocket` |
| 後回し（parked） | 🎉 | `hooray` |
| 作り直し | 👎 😕 👀 | `-1` `confused` `eyes` |

**変えられる。** GitHub で普段使っている絵文字とぶつかるなら `orch.config.json` で割り当て直す。

```json
{ "stamps": { "approve": "rocket", "park": "eyes", "redo": ["-1", "laugh"] } }
```

使えるのは GitHub の8種類だけ。`rocket` `hooray` `eyes` `+1` `-1` `laugh` `confused` `heart`。

**作り直しは、AIが投稿したコメントのリアクションしか見ない。** Issue本文に押した
作り直しスタンプは無視される。本文で意味を持つのは承認と後回しの2つだけ。

```bash
node "$ORCH" stamps --human   # 今の割り当てとフッタの文面
```

コメントのフッタは、この割り当てに合わせて書く。文面は `orch stamps` の `footer` が出す。

> 既定の選び方。**押し間違いが静かに状態を変えるのが一番まずい**ので、
> 普段使いされる絵文字を避け、意味が近いものを近い役割に当てている。
>
> - 後回しに 👀 を使わない。「見ています」の意味で押されて、意図せず parked になる
> - 後回しは 🎉。この流れで自然な意味を持たないぶん、押し間違いが起きにくい
> - 作り直しに 😄 を使わない。casual な「笑った」で作り直しが走る
> - 作り直しは 👎（違う）／ 😕（腑に落ちない）／ 👀（読むのが大変）

## 有効条件

1. 押したのが `orch.config.json` の `account` 本人であること。**他人の同じスタンプには反応しない**
2. 承認スタンプの作成日時 > 対象（コメント or Issue本文）の更新日時。古い承認は無効
3. 理解メモの承認は、確認事項がすべてチェック済みのときだけ有効

## 起点

Issue本文の承認スタンプが起点。担当が自分でも、押すまでAIは何もしない。
本文スタンプなしで着手してよい判定は必ず state.json の登録で行い、本文の目印では判定しない。

後回しスタンプが付くと `parked`。外して承認スタンプを押し直せば `sizing` から再開する。

## 承認の扱い（PR）

| 変化 | 承認 | コメント |
|---|---|---|
| 修正依頼への対応でプッシュ | 無効 | 新規投稿、旧を折りたたみ |
| マージ後のbase切り替え（SHA不変） | 維持 | そのまま |
| 判断不要の競合を自動解決 | 引き継ぐ | SHAを書き換え＋事後確認に記録 |
| 判断が必要な競合 | 無効 | 新規投稿して needs-human |

承認を無効にする場合は新規コメント、引き継ぐ場合は同じコメントを編集。
修正後のセルフレビューは、前回承認したSHA（`approvedSha`）からの差分だけが対象。

## 取得方法

検索はしない。state.json が持つ `commentId` のリアクションを直接見る。
新規Issueと回答だけ「前回実行以降の更新」で差分取得する。
