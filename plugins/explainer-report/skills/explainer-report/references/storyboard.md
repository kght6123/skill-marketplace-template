# 解説動画の絵コンテ：何を描けば分かるか

動画が分かりにくくなる一番の原因は、「箱・矢印・ラベル」だけで作ることにある。
角丸の四角に「承認待ち」と書いて矢印でつないでも、どんな台本にも使い回せる挿絵になるだけで、視聴者は何も見ていない。
この参照は、1文ごとに「画面に何があり、何が起きて、視聴者が何を分かるか」を決める手順を書く。
**絵コンテ表ができるまで、Manim のスクリプトを書かない。**

考え方は次の2つから取り入れた（どちらも MIT ライセンス。手法だけを取り入れ、作例や文章は写していない）。
- [HeyChengC/vibe-knowledge-film](https://github.com/HeyChengC/vibe-knowledge-film)：6つの描き方、描かない判断、形の探し方、1カットごとの3つの問い、見て直す表
- [cth9191/animate](https://github.com/cth9191/animate)：安く確認できる段階を先に挟む流れ、1つの主役、色の意味、数で測るレビュー

## 1. 形を探す
概念（変更点・仕組み・問題）ごとに、上から順に問う。答えが出たら下は問わない。

| 問い | 答えが「はい」なら | 例 |
|---|---|---|
| それ自体が物か | 物そのものを描く | 画面、ボタン、ファイル、表の行、ログの1行、通知 |
| 過程・手順か | 小さな具体例を1つ選び、各段階を最後までやってみせる | 3件の申請が順に処理される、1回のリクエストがキャッシュを通る |
| 量・程度か | 1本の物差しを決め、同じ物差しで2〜3個を測る | 待ち時間を同じ時計で、件数を同じ升目で |
| 視聴者の頭の中のことか | 5秒の小さな試しをその場で起こす | 「どこを押せば戻れるか」を探させる |
| 規則・法則か | 例を2〜3個見せてから、1枚の図にまとめる | 3つの失敗例 → 共通点を表に |
| どれでもない | 描かない。文字だけにする | 判断、方針、まとめ |

見つけた形を強くする問い：
- **視聴者が普段どこで見ているか**：その場面から入る（いつもの一覧画面から寄っていく）。
- **尺度を1段変えると何が見えるか**：画面全体 → 1つの行 → 1つの値、と寄ると原因と結果がつながる。
- **壊れるとどうなるか**：正しく動いているときは何が働いているか見えない。不具合修正なら、**直す前の失敗を画面で実際に起こしてから**直した動きを見せる。

形の描き方：
- 実物（`references/screen-capture.md` で撮ったスクショ、実際のコードの抜粋、実際のログ）があれば、`screenshot()` や `Code` で実物を見せる。作り物の画面を本物のように描かない。
- 箱・矢印・点線は**説明の小道具**としてだけ使う。主役にしない。主役は、日常の言葉で名前を言える物にする。

## 2. 1文ごとに描き方を選ぶ
字幕の1文ごとに、次の6つから1つを選ぶ。

| 描き方 | 使う文 | やること |
|---|---|---|
| ① 試させる | 「〜と思うかもしれない」、冒頭 | 画面に物を出し、視聴者に反応させてから字幕で言葉にする |
| ② 文のとおりに描く | 出来事、例、事実 | 文にある名詞が画面にあり、文にある動詞が画面で本当に起きる |
| ③ その場でやってみせる | 方法、仕組み、「だから〜になる」 | 小さな具体例で手順を最後まで動かす。数は本当に計算した値にする |
| ④ 並べて比べる | 変更前と後、案Aと案B | 同じ配置に並べ、違いは1か所だけにする |
| ⑤ 1枚の図にまとめる | 「なぜそうなるか」の答え | すでに出た物を表やグラフに並べ直す。例のあとに置く。1本に2〜3回まで |
| ⑥ 文字だけ | 問い、名付け、定義、結論、方針 | 新しい絵を出さない。前の画面を止めておくか、短い文字だけ出す |

描かない判断：
- **問い・名付け・結論・方針の文には、新しい絵を付けない。** 直前に演じて見せたことを、結論の文でもう一度描かない。その間は、視聴者が今見たことを考える時間になる。
- 全体のおよそ5分の1が「⑥ 文字だけ」になるのがよい。0なら結論まで描いている。半分なら形が見つかっていない。
- 年・人・Issue 番号・PR 番号は、今の画面の端に小さく出すだけにする。そのために場面を変えない。

## 3. 絵コンテ表
台本と一緒に書く。1文1行。

| # | 字幕 | 描き方 | 画面に何があり、何をしているか | 画面の小さな文字 | 視聴者が分かること | 音 |
|---|---|---|---|---|---|---|
| 1 | 申請は、まず承認待ちになる。 | ② | 申請の一覧画面。新しい行が「承認待ち」の列に入る | 申請 #12 | 申請はすぐには通らない | pop |
| 2 | 承認者が見るまで、ここで止まる。 | ② | 行が灰色になり、時計の針だけが進む | 3日 | 待っている間、何も進まない | なし |
| 3 | なぜ止まるのか。 | ⑥ | 画面を止める | | （考える間） | 無音 |

表の前に書くこと：一文で言える主張、全体の主役（ずっと画面にある1つの物）、物差し、色の意味（1色1意味。例：黄＝今話している物、赤＝失敗）、どの2カットが同じ画面か。
表の後に書くこと：画面に出す数がどこから来たか（事実メモのどの行か）、どこが図解のための簡略化か。

書いたら確かめる：
- 「字幕」の列を隠し、「画面に何があり、何をしているか」だけを読んで内容が分かるか。
- 字幕の名詞が、すべて画面にあるか。
- 別の台本に差し替えても成り立つカットが無いか（あれば挿絵になっている）。
- 1つの場面が2〜5文を受け持ち、1文ごとに変わるのは1か所だけか。
- 「なるほど」となる1カットはどれか。その前に準備があり、後に止まる間があるか。
- 最後は最初の画面に戻り、変更の結果が見えるか。

## 4. 1カットごとの3つの問い
字幕と小さな文字を隠して答える。答えがあいまいなら作り直す。
1. **これは何か**：日常の言葉で（一覧画面、申請の行、エラーのログ）。「いくつかの点」「線」「箱」は不合格。
2. **何をしているか**：動詞1つで。字幕の動詞か、その直接の結果。
3. **何が分かったか**：1文で。前のカットとは違うこと。

## 5. 全体の決まり
- **主役を1つ**：最初から最後まで画面にある1つの物（対象の画面、1件の申請、1つのリクエスト）。形は変わってもよいが、色など見分けられる印を1つ残す。
- **色は1色1意味**：決めた意味のある色を飾りに使わない。Mermaid 図と同じ色の意味にする。
- **例が先、理屈が後**：名前・定義・結論は、例を見せたあとに出す。冒頭の10秒は、何かが起きるところを見せる。
- **2〜4秒ごとに何か1つ変わる**：動き、出現、寄り、反応。ただし⑥の止める間は除く。
- **同時に動く主役は1つ**。小さな文字は1カットに1つまで。
- **使わない手**：画面中央のタイトルに背景のグラデーション、すべてをフェードインで出す、隅のラベル、意味のない光や粒子。

## 6. 安く確認できる段階を先に
描画には時間がかかるので、安い段階で直す。

| 段階 | 作るもの | 標準 | ロング |
|---|---|---|---|
| 1. 筋 | 主張・主役・絵コンテ表 | 自分で第3節の確認をする | ユーザーに見せて確認を取る |
| 2. 見た目 | 一番違う2〜4カットの静止画 | 自分で第4節の3つの問いを通す | ユーザーに見せて確認を取る |
| 3. 下書き | `QUALITY=l` の通しの動画と一覧画像 | 第7節の検査を通す | 同じ |
| 4. 本番 | 既定画質の動画 | 第7節の検査を通す | 同じ |

静止画は下書きの動画から切り出す：`python3 scripts/review_video.py out/draft.mp4 --stills 4,18,40`。
ユーザーが「確認なしで作って」と言ったら確認は待たないが、表と静止画は作って自分で確かめる。

## 7. 見て直す
描画したら、コードではなく画像を見る。最低2回、「問題を書き出す → 直す → 同じ時刻を撮り直して、直ったことと他が壊れていないことを確かめる」を繰り返す。

```bash
python3 scripts/review_video.py out/explain.mp4   # 一覧画像・スマホ幅の一覧・数で測る検査
```
- 検査が出す問題：画面が4秒以上変わらない区間、文字のはみ出し・字幕へのかぶり・文字の重なり（`VoiceScene` が記録）、速すぎる字幕（1秒9字を超える）。
- **文字の検査を目より信じる**。一覧画像では、はみ出した文字が普通に見えることがある。
- 一覧画像を見て、次の表で確かめる。

| 見えたもの | 直し方 |
|---|---|
| 主役が小さく、画面の真ん中に縮こまっている | 主役が画面の幅の6割以上になるように置き直す |
| 字幕と小さな文字を隠すと、何か分からない | 実物（スクショ・コード・ログ）に替える。見覚えのある画面から寄っていく |
| 字幕の名詞が画面に無い | 描き足すか、文を直す |
| 1文の間に画面が3〜4か所変わる | 文を2つに分けるか、小さい方の変化を消す |
| 何文も続けて画面が変わらない | 文ごとに変わる1か所を表に書き直す |
| 隣り合う場面が同じに見える | 片方の寄り・配置・主役の状態を変える |
| 場面の切り替えの途中に、何をしているか分からないコマがある | 「寄る」「開く」「差し替わる」など名前のある動きにするか、0.5秒以内に縮める |

最後に3回見る：音を消して字幕を隠して1回（画面だけで分かるか）、字幕だけを読んで1回（文がつながるか）、上の検査と表で1回。
渡すときは、まだ満足していないところ、確かめていないところをそのまま書く。
